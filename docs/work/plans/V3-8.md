# V3-8 · Tables: a modern table library with search and filters

**Agent:** (unclaimed) · **Branch:** `v3/V3-8-tables` (base `design-v3`) · **Port:** 5238
**Approved:** yes (26 Nov 2026): **TanStack Table**, pages of 25 with "Show more"

## Why
You asked to stop using our current tables (26 Nov).
- Today there are **68 tables in 47 web files**. Only 6 screens use our shared `DataTable` (sort, density, columns, CSV); the rest are hand-written `<table>`s with their own filters, or none.
- We want one table everywhere, with: global search, filters per column (text, pick-list, number / date range), sorting, column show/hide, density, pagination or virtual scroll, sticky header, CSV / Excel export, row click to open, and cards on a phone.

## Options (checked 26 Nov 2026: versions and licences from npm)
| Option | What it is | Fit |
|---|---|---|
| **TanStack Table v9** (`@tanstack/svelte-table` 9.3, MIT, Svelte 5) | Headless: it gives the sorting, filtering, faceting, grouping, pagination and column state; we draw the table with our tokens | **Recommended.** The table looks like the rest of v3 (light and dark), stays small, works with our `DataTable` props, and screens move over one by one. We build the filter UI once. |
| SVAR DataGrid (`@svar-ui/svelte-grid` 2.7, MIT, Svelte 5) | Ready-made grid: filters, sorting, in-cell editing, virtual scroll | Fastest to a full grid, but it has its own look to restyle, and it is heavier. Good if you want spreadsheet-style editing. |
| AG Grid Community (36.x, MIT core) | Very complete grid, framework-agnostic | The most features, but large; several advanced features (row grouping, Excel export) are in the paid Enterprise edition. |

## Proposed approach (with TanStack)
1. Rebuild `components/page/DataTable.svelte` on TanStack Table, keeping its props so the 6 current screens keep working.
   - New: a search box, a **Filters** button opening one panel with a filter per column (from the column type: text / pick-list with counts / number range / date range), filter chips you can remove, "Clear all", and filters kept in the address.
2. Move the hand-written tables to `DataTable` in batches by area. List pages first: POs, Shipments, Truck desk board, Stock, Sales, Warehouse expenses, Master data tabs, Users, Audit. Then drawers and details.
3. Dashboard tables (inside chart cards) stay simple tables, with the new look only.
4. A Playwright check per migrated page: search narrows the rows; a filter + chip + clear; sort; CSV has the filtered rows.
