## Goal
One **Settings & alerts** workspace instead of scattered pages:
- an internal menu on the left, the chosen section on the right;
- **Alerts** moves in from the main sidebar;
- no empty placeholder sections: only things that work today.

## Proposed structure

**Main sidebar (Operations):** one entry **Settings & alerts** replaces "System settings & logs" and "Alerts". It shows the unread count. The bell in the top bar opens Alerts.

**Workspace, at `#/system/<section>`:**
```
┌──────────────────────┬──────────────────────────────────────────────┐
│ ALERTS               │  Alerts                                      │
│ ● Alerts       (12)  │  What needs attention, and what you were     │
│   My notifications   │  told.                                       │
│                      │  [Open exceptions | Inbox]                   │
│ RULES                │  Type ▾  Severity ▾  Status ▾  Area ▾  Date  │
│   Approvals          │  ┌──────────────────────────────────────────┐│
│   Exchange rates     │  │ ● Critical  Delay  RAD 812K 669 h behind ││
│   Thresholds         │  │ ● High      Unpaid fee  KBV 894T  …      ││
│                      │  └──────────────────────────────────────────┘│
│ PEOPLE & SYSTEM      │                                              │
│   Users & access     │                                              │
│   Audit log          │                                              │
│   Integrations       │                                              │
└──────────────────────┴──────────────────────────────────────────────┘
```
- The left menu is part of the page, not a second app sidebar:
  - narrow (220 px), with small group labels and icons;
  - the chosen item is highlighted;
  - a person sees only the sections their role opens.
- On a phone the menu becomes a row of pills above the content.
- Each section has a title and a one-line description, then its content in a compact layout: tables, toggles and short forms, not a long page of cards.
- **Address:** `#/system/alerts`, `#/system/users`, and so on. Old addresses (`#/notifications`, `#/users`, `#/audit`, `#/integrations`, `#/system/settings`) open the right section, so links in notifications, dashboards and emails keep working.

### Sections
1. **Alerts** (everyone):
   - **Open exceptions:** the Alerts centre data, with filters for type, severity (Critical / High / Medium / Low), status, area (purchasing, loading, fleet, fees, deliveries, warehouse) and date. Each row links to the record.
   - **Inbox:** the current notifications (All / Unread, Mark all read), plus area and date filters. The area comes from each notification's link.
   - People who don't see exceptions get only the Inbox.
2. **My notifications** (everyone): email / SMS for money news (exists). Also shows what reaches this person in-app, by role.
3. **Approvals** (directors, admin):
   - advance payments need director approval (exists, with a confirm dialog before switching);
   - the server's business rules (PO approval, loading allowance, substitutes, fee amber / red days, cost allocation), shown **read-only** with "set in the server configuration".
4. **Exchange rates** (directors): the monthly average and closing rate per currency, with **Approve rate** (Save / Cancel, confirm). The API already exists; only the screen is new.
5. **Thresholds** (directors; planners view):
   - planned-vs-actual behind / over (moved here from the Period plans tab, which keeps a link);
   - stock cover and slow / fast thresholds (API exists, no screen yet).
   - Save / Cancel / Reset to defaults.
6. **Users & access** (`users`): the current page.
7. **Audit log** (`audit`): the current page.
8. **Integrations** (`integrations`): the current page.

### Left out on purpose (no duplicates, no placeholders)
- **General settings:** nothing configurable exists today.
- **Company settings:** company data is Master data → Companies, used daily by the office. A copy here would be a duplicate; the workspace links to it from Approvals.

## Decisions for you
1. **Severity on the inbox:** notifications have none today.
   - (a) Severity, type and status filters on Open exceptions only; the Inbox gets area, date and read filters. No server change. **Proposed.**
   - (b) Also store a severity and type on every notification. This is a server and mock change, and older notifications would show "not set".
2. **Management → Settings:** remove it from the Management menu so there is one place for settings (proposed), or keep both.
3. **Business rules from `config.toml`:** show them read-only (proposed), or leave them out.
4. **Exchange rates and stock thresholds:** add their screens now (proposed: the API exists and they have no screen), or later.
