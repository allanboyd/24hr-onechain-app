## Goal (your request, 26 Nov)
The Management pages become part of our app (Svelte screens), with their numbers coming from **our database**, the way Live dashboards do.
- **Reuse** the queries, report builders and views behind Live dashboards. No second set of formulas.
- **Keep** the report's look and its indicators (cards, charts, tables, wording). The report file (V3-2) stays only until each page is replaced, then it is removed.

## 1. How it is built (one clean path)
```
database ─► API (NestJS) ─► shared builders in packages/api (reports.ts, performance.ts, landed.ts, metrics.ts, dashboards.ts)
                                   ▲ same functions the Live dashboards use; the mock client uses them too
         GET /v1/management/:page?period&warehouse&supplier&brand  ─► Management screen (Svelte, report look)
```
- One endpoint per page, built from the **existing** builders. New figures are added to those builders (or to the metric registry), so Home and Management can never disagree. `metrics.test.ts` checks the numbers match.
- The same filters as the report: warehouse (Combined / Congo, Goma / Rwanda, Gisenyi / South Sudan, Juba), supplier, brand, Day / Week / 30 days / Year to date, a date range.
- Access: `reports` (as now). Scoping by company (Group view) works like the dashboards (`scopeSource`).
- UI: the report's components rebuilt with our tokens: KPI cards with a sparkline and a delta chip, waterfall, bars, donut, tables with the new `DataTable`.
